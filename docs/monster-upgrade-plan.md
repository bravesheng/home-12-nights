# 舊怪物照第五世界的做法重做

2026/11/08 開始。第一到第四世界的怪物原本大多用球、圓柱拼起來，貼圖是簡單的畫布圖案。現在照第五世界 7 隻新怪物的做法，一隻一隻重做，每做好一隻給設計師看過再做下一隻。

## 做法

做法跟第五世界一樣，程式在 `js/render3d.js` 的「舊怪物照第五世界的做法重做」那一段。

- **網格**：用雕的，不再用球拼。
  - 頭用 `sculptGeo`：單位球上的點經過 `pt` 函式變成五官。
  - 身體用 `loftGeo`：一圈一圈的斷面。
  - 手腳、手指用 `tubeGeo`。
  - 不會分開動的零件用 `mergeParts` 合成一個網格，少畫幾次。
- **貼圖**：逐點畫。雜訊用 `fbm3`，在單位球或圓柱上取樣，繞一圈沒有接縫。
  - 用 `m5Tex` 預先畫好，存成 `tex/m5-<key>.webp`。
  - 改了畫法要跑 `node tools/make-monster5-tex.mjs`，新檔名要加進 `sw.js` 的 `ASSETS`。
- **材質**：
  - 有明暗、被手電筒照到會反光：`ownPhong`、`ownLM` 加 `shade`。
  - 需要時用 `withDetail` 疊照片細節。
- **接上遊戲**：在自己那一段最後登記 `UPG.<kind> = { build(r, g), sync(e, r, t, p, dt), view }`。
  - `view` 是圖鑑的鏡頭，格式跟 `BOOK_VIEW` 一樣。
  - `buildEnemy`、`syncEnemy`、圖鑑會先用 `UPG` 的；舊的 `build*`、`NEW_BUILD`、`BOOK_VIEW` 不用動（舊的程式之後再清）。
  - `syncEnemy` 一樣會先做共用的部分：位置、面向玩家、`r.mats` 的透明度、`r.eyes` 的閃爍。
  - 花（眼球花、向日葵眼、千眼菇）不是怪物，模型在別的地方，要自己找地方接。
- **分開做**：每個世界的怪物寫在 render3d.js 自己那一塊「第 N 世界重做的怪物」裡面，`sw.js` 的 `ASSETS` 也有每個世界自己的一行註解，新檔名加在那一行下面。這樣幾個 session 同時做，合併時才不會打架。
- **不能改的**：
  - 怪物的大小、碰撞、行為（`game.js`、`world*.js`）。
  - 顏色、特徵：例如黑影一定是黑的、紅眼睛。
- **設計師的要求**：寫實風、不要可愛風。有設計圖的要「跟我畫的一樣，不要亂改」。

## 黑影（2026/11/08）

- **身體**：用很濃的黑煙凝成的人形，大約 1.85 公尺。
  - 駝著背、頭往前伸。
  - 長長的手臂垂到膝蓋，手指又細又長。
  - 腰以下散成一縷一縷的煙，飄在地上。
- **臉**：沒有五官，只有兩個很深的眼窩，裡面的紅色瞳孔發光，照得眼窩周圍紅紅的。
- **煙**：身上一直冒出黑煙，外面有一層慢慢轉的薄煙，所以邊緣看起來一直在飄。
- **動作**：追你的時候更往前傾，頭偶爾抽一下，手臂跟著晃。
- **在遊戲裡的樣子**：
  - 黑暗中只看得到黑色的輪廓和兩個紅點。
  - 被手電筒照到才看得到頭和身體的形狀。
- **效能**：主選單的背景就有一隻黑影，所以模型開遊戲時就蓋好了，晚上出來不會卡一下。

## 第二世界重做的怪物

程式在 `render3d.js` 的「第二世界重做的怪物」那一塊，小工具和名字都用 `w2` 開頭（`w2M`、`w2Grid`、`w2TubeIn`、`w2PaintRect`），貼圖是 `tex/m5-w2*.webp`。

### 花怎麼接（向日葵眼、千眼菇，眼球花也能用）

- 花不是怪物，`buildEnemy`／`syncEnemy` 不會經過它們。
- `buildFlower`、`syncFlower` 開頭各有一個鉤子：`UPG.<ptype>.flower = { build(f, g), sync(f, r, t, p, awake) }` 有登記就用它。
  - 鍵是花的 `ptype`：眼球花 `eye`、向日葵眼 `sunflower`、千眼菇 `shroom`。
- 同一個 `UPG.<ptype>` 也登記 `build`／`sync`：做一朵假的花放在怪物的位置（`w2FakeFlower`、`w2FakeSync`）。
  - 這樣 `bake5()` 會把花的貼圖也存成圖檔，`?model=sunflower` 也看得到。
- 圖鑑的鏡頭還是用 `BOOK_VIEW` 裡花的那一格（花的大小沒變）。
- 手電筒的影子只算花瓣、莖、花盤、菇傘、菇柄；眼球、眼皮、眼淚的影子藏在眼窩裡看不到，不算。

### 怎麼量效能

- 三角形和畫的次數：把怪物放進遊戲裡，前後整個場景數一次相減（看板算 2 個三角形）。
- 算繪時間：連續呼叫 `Renderer.render` 好幾次、用 `readPixels` 等它畫完，取最快的一批。
  - 比 FPS 穩，但 2026/11/08 四個 session 一起跑無頭瀏覽器（電腦負載 18～26），同一個版本兩次還是可能差一倍，只能看大概。
  - 無頭瀏覽器用 CPU 算每一個像素，凹凸貼圖、反光這些逐像素的計算特別吃虧；平板的顯示卡比較怕畫的次數多。最後還是要在平板上看。

### 向日葵眼（2026/11/08）

- **花盤**：用網格雕出來，鋪滿往中間尖、有條紋的葵花籽，籽有凹凸（凹凸貼圖 `w2sfDiscH`）。
  - 靠近眼睛的籽腫成暗紅色的肉疙瘩，血管從眼睛爬到花盤上。
- **眼睛**：
  - 埋在一圈濕濕、腫起來、往中間皺的肉裡，只露出前面一塊。
  - 厚厚的肉眼皮，會眨、被手電筒照到會瞇起來。
  - 眼白滿是血絲，虹膜灰色、瞳孔周圍一圈褐色。
  - 瞳孔盯著你時放大、被燒到時縮小；眼球偶爾自己抽動一下。
- **花瓣**：兩圈，有好的、快枯的、枯掉捲起來的，邊緣破破的、有破洞和爛斑。
- **背面**：毛毛的綠色花托和尖尖的花萼。舊版的眼球會從背面穿出來，新版沒有。
- **莖和葉子**：毛毛的莖，上半段有兩條暗紅色的血管。三片垂下來、有枯黃和蟲洞的大葉子。
- **頭**：轉頭、低頭都繞著莖的頂端轉，白天睡覺時整顆垂下來。
- **效能**：
  - 三角形 4542 → 6246，每朵畫的次數 48 → 9。花瓣、花萼、莖、葉子共用一張圖，合成兩個網格。
  - 6 朵一起時的算繪時間：黑暗中新版 275 毫秒、舊版 217；開手電筒新版 214、舊版 242（只量了一次，雜訊很大）。

### 千眼菇（2026/11/08）

- **菇傘**：用 `sculptGeo` 雕，凹凸不平、邊緣往內捲（看得到厚厚的粉白色菌肉）。
  - 暗紅色、濕濕亮亮的，中間深、邊緣淡。
  - 一絲絲往下的纖維、凸起來的白色疣（凹凸貼圖 `w2muCapH`）。
- **眼睛**：15 顆，大大小小。
  - 每顆周圍一圈腫起來、充血的肉：一小片圓形網格貼著菇傘鼓起來，貼圖座標照菇傘算、跟菇傘合成一個網格，看不出接縫。
  - 上下眼皮（`InstancedMesh`），偶爾眨一下，被手電筒照到時合起來。
  - 眼白哭得紅紅的、滿是血絲，褐色的虹膜，每顆都轉過來盯著你。
- **眼淚**：每顆眼睛一道細細亮亮的水痕，沿著菇傘流到邊緣（菇傘那裡濕濕暗暗的）。
  - 淚珠沿著水痕滑下來、在邊緣變大、掉到地上，地上一個個小水窪。
- **底下**：一片片奶油粉色的菌褶、垂下來破破的菌環；奶油色的菇柄有纖維和一圈圈的鱗紋，底部腫成球、包在菌托裡。
- **效能**：
  - 三角形 9708 → 12922，每朵畫 9 次（跟舊版一樣）。
  - 6 朵一起時的算繪時間（量三次）：黑暗中新版 232～510 毫秒、舊版 164～334，差不多；開手電筒新版 355～436、舊版 188～380，新版大概慢四成。之後把眼球、眼皮、眼淚的影子關掉了（沒有再量）。

### 草叢人（2026/11/08）

- **草叢**：一叢比腰還高的長草（`hairGeo`，新的草葉貼圖 `w2grBlade`：細長的葉子、中間一條葉脈、幾片枯黃的）。
  - 平常就跟著風慢慢搖；躲著走的時候搖得更快更大、整叢晃；撲過來時草往後倒。
- **臉**：用 `sculptGeo` 雕的長臉，被光照到才有明暗。
  - 兩個又深又陡的黑洞眼睛，最裡面一點紅光。
  - 咧開到耳邊、像一彎月亮的大嘴：嘴唇鼓起來、嘴裡凹進去，上下兩排咖啡色、歪歪的爛牙。
  - 皮膚像乾掉的泥巴（一道道裂紋），頭頂是粉紅色、像腦一樣皺皺的，長滿會搖的草。
  - 紅色和綠色的痕跡從眼睛和嘴角往下流。
- **身體**：乾瘦、駝背的長身體（`loftGeo`），胸口隱約的肋骨，纏著兩條藤蔓、腰下伸出鬚根。
  - 兩隻細長的手、像樹根的長手指；撲過來、抓住你時往前伸到腳邊。
  - 頭會歪、偶爾抽一下，抓到你時一直抖。
- **效能**：
  - 三角形 2826 → 7246，每隻畫的次數 33 → 12。
  - 3 隻一起時，無頭瀏覽器每秒 3.5～4 幀，舊版 2.5～4.8；算繪時間新版 190～313 毫秒、舊版 195～230。

### 大嘴觸角蟲（2026/11/08）

- **身體**：用 `sculptGeo` 雕的大蛞蝓（單位球的 y 軸當成身體的長軸）：前面鈍鈍的、後面拖成尖尾巴，底下是扁平的腹足。

- **腹足邊上**：一排長著圓頭的小芽。
- **效能**：
